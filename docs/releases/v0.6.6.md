**Changed — a single-zone valve stops saying "Zone 1" on every entity.** `Zone 1 Temperature`
is now `Temperature`, `Zone 1 Flow` is `Flow`, and `Zone 1 Hex` is `Hex`. With one zone there
is nothing to disambiguate, so the prefix was pure noise — the same reasoning that dropped it
from the outlet switches in 0.6.0, applied to the entities it was missed on.

**A two-zone valve keeps its prefixes**, because `Temperature` alone would be ambiguous
across zones there.

**Changed — the per-outlet run-time sensors take the fixture name too.**
`Zone 1 Outlet 1 Max Run Time` becomes `Rainhead Max Run Time`, so it sits directly beside
the `Rainhead` switch it describes instead of being named by a position the switch no longer
uses. An outlet whose type code is not one this integration can name keeps the positional
form, exactly as its switch does.

**Your entity IDs do not change.** All of this is display names only — the underlying
identifiers are untouched, so every automation, script and dashboard card keeps working.
That is deliberately unlike the outlet rename in 0.6.0, which did change IDs because it
replaced names carrying no information at all. Tidier labels are not worth breaking working
automations for.

**Internal — the naming rules now live in one place.** `zone_label` and `outlet_name` moved
into `entity.py`, which every platform already imports. The run-time sensor needs the same
outlet name the switch uses, and reaching from the sensor platform into the switch platform
to get it would have coupled the two for no reason. The duplicate-fixture rule from 0.6.0 —
two showerheads on one zone become `Showerhead 1` and `Showerhead 2` so their IDs stay
distinct — moved with it and is unchanged.

**A single-zone valve now reads:**

```text
Shower Valves            switch
Temperature              number
Flow                     number
Rainhead                 switch
Showerhead               switch
Handshower               switch
Rainhead Max Run Time    sensor
```

**Upgrading:** update through HACS and restart Home Assistant. Nothing to change — the
entities appear under their new labels and keep the IDs they already had.
