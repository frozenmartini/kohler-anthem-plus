The Konnect app shows **three firmware versions** for one shower — interface, valves, and
gateway — and this integration had a single `Firmware` entity reporting whichever it found
first. On one of the reference system's two valves, that was the **artwork bundle** version.

## `Firmware` was showing the wrong number, for two reasons

**The `about` block was being read one level too shallow.** It is nested inside the record's
own `configuration` key, not at the top level, so `configuration.get("about")` was always
`None` — and every diagnostics report said `about_keys: []` on hardware that populates the
block in full. The block was there the whole time, with every version in it.

**And `about.firmware` is a mapping, not a string** (`version` / `latestVersion`), so it would
not have parsed even at the right depth.

Together those meant the property fell through to the OTA blocks — where a valve whose
`otaReportedProperties` describes **Assets** reported the artwork version as its firmware:
`2.00` where the app showed 2.2, on one of two otherwise identical valves. Its sibling, which
happens to carry an Application block, read correctly. Nothing about the hardware differed;
only which block Kohler's cloud happened to populate.

## Three entities, each honest about its own source

| Entity | Reads | Reference system |
| --- | --- | --- |
| `Interface Firmware` | `about.uI2.firmware` | 2.2 on both valves |
| `Valve Firmware` | `about.primaryValve.firmware` | **10 on one, 11 on the other** |
| `Second Valve Firmware` | `about.secondaryValve1.firmware` | two-valve systems only |
| `Gateway Firmware` | `about.gateway.firmware` | 00.74 on both |

**Two valves on one account can be on different firmware, and the app hides it** — Konnect
shows 10 for both where the record says 10 and 11. Two showers that should be identical are
not, and nothing else surfaces that.

`Interface Firmware` keeps the `_firmware` unique id the old entity had, so its history and
any automation referring to it survive the rename. The other three are new, diagnostic, and
disabled by default like the rest.

An Assets-only record now reads `unknown` rather than reporting the artwork version — a blank
is better than a confidently wrong version in a bug report. An **untyped** OTA block is still
read, though: the reference install carries no `firmwareType` at all, and refusing it would
trade one wrong answer for a blank on hardware that reads correctly today.

Diagnostics reports `about_keys` through the same resolver, so it stops claiming `[]` on
hardware that has the block.
