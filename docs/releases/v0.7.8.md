**The `gcs-usage` parameters are `FromDate`, `ToDate` and `Interval` — PascalCase.** That is
why 0.7.7's probe failed on all fifteen candidates, and it is now recovered rather than
guessed.

The first probe returned an identical generic HTTP 400 to every candidate — **including a
bare call with no query string at all.** That uniformity was the finding: if a real parameter
had been recognised and merely malformed, the answers would have differed. None of the names
was ever recognised as a parameter, so nothing distinguished a fully-formed request from an
empty one.

**The contract comes from the Konnect app's own Retrofit annotations**, read out of the APK:
`getAnthemWaterUsageData` on `com/kohler/hermoth/data/network/DeviceApiCall` declares

    GET /devices/api/v1/device-management/gcs-usage/{deviceId}
        ?FromDate=<date>&ToDate=<date>&Interval=<WEEK|MONTH|YEAR>

Three query parameters, no headers, no body. `Interval` is uppercase, from the const-strings
in `WaterUsageViewModel`. Every other endpoint in this API is camelCase — this family is the
outlier, which is exactly what made the original guess reasonable and wrong.

**The response is the per-month series.** `AnthemWaterUsageModel` carries
`gcsUsageDataDetailsList[]`, one entry per period with `timestamp`, `volume`, `onDuration`,
`averageBlendTemperature` and `numberOfTimesValveSwitchedOn`, plus min/max/avg rollups across
the range. Summed over months, `volume` is directly comparable to the figure the app charts —
which is what the 8224-versus-5613.49 question needs.

**One element is still unverified: the date format.** The decompile did not pin the
formatter, so the action now tries `yyyy-MM-dd` first, then ISO-8601 with a `Z`, then
`MM-dd-yyyy` — all three appear in the app's string pool. A bare call is kept as a control,
so a success sits beside a known failure and proves the parameters were the difference.

**Run `kohler_anthem_plus.probe_usage` again.** Six candidates now instead of fifteen, and
five of them carry a contract read from the app rather than invented.

**The API notes are corrected.** `docs/gcs/api.md` recorded this endpoint as "exists, wants
parameters" and now carries the full contract and response shape; `docs/hub/cloud_api.md`
records that `hub-usage` takes the same three.

**Tests: 44.** The candidate check now also asserts every parameterised query carries all
three PascalCase names, so a regression to camelCase fails here rather than against live
hardware.
