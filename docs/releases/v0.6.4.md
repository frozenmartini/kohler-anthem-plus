**Fixed — toggling an outlet silently reset the flow you had set.** Set the Flow number to
40 %, turn on the rainhead, and the flow went back to 100 %. Every outlet toggle rewrote the
whole valve word with the default flow, because the write path deliberately never carries
flow forward.

**That rule was right and is unchanged; it just did not survive Flow becoming a control.**
`async_apply_valve` refuses to inherit the valve's flow byte so that nothing silently adopts
whatever the wall panel last wrote — a real problem, and the reason the rule exists. But it
was written when there were no flow entities at all, on the explicit reasoning that no
caller could ever *mean* a particular flow. 0.6.0 made that untrue by adding the Flow
number, and the rule was not revisited.

The distinction is between the *valve's* byte and a value **Home Assistant itself holds**.
The run-time-cutoff restore already draws exactly that line, replaying a flow it observed
rather than defaulting. An outlet toggle is the same case: the user set a flow, so opening
an outlet should not undo it. The valve's idle byte is still never read — it remains
untrustworthy, as 0.6.3 established.

The chosen flow now lives on the valve rather than inside the Flow entity, because both
entities need it: the number displays it while the shower is off, and the outlet switches
send it. An installation where nobody has touched the Flow number behaves exactly as
before, since the value it starts at is the same 100 % an unspecified write already sent.

**Documented — why the Shower switch is not redundant with the outlet switches.** A question
worth answering in the code rather than only in an issue thread. Both run water, but they
answer different questions: an outlet switch opens *one* outlet at whatever temperature the
zone already holds, which is manual control one outlet at a time. The Shower switch runs the
shower the owner configured — outlets, temperature and flow together, in one command, from a
preset edited in the Konnect app rather than in this integration. Change that preset and the
switch starts something different with no code change. They overlap only at the *off* end,
where both stop the water.

**Upgrading:** update through HACS and restart Home Assistant. No entities are renamed or
removed and no config changes are needed.
