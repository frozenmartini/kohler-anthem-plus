> ⚠️ **Breaking change — what you will see right after updating.**
>
> **A Repairs card appears** (Settings → System → Repairs): *Old debug captures can be
> deleted.* Every version before 0.4.1 wrote a developer capture to
> `/config/kohler_anthem_plus_raw/` on every install — the author's own tooling, switched on for
> everyone by mistake, never pruned. Nothing reads or writes that folder any more. **Submit**
> deletes it (only if it holds nothing but the files this integration wrote); **Ignore** keeps
> it. The files are inert either way. Your Report Log files, inside the integration folder, are
> not touched.
>
> **One entity is removed:** the *Start new MQTT capture* button on the device page
> (`button.anthem_valve_start_new_mqtt_capture`; on a controller-only account it sat on the
> controller instead, e.g. `button.anthem_plus_start_new_mqtt_capture`). It rolled the capture
> that no longer ships. Its registry row is cleaned up automatically; a dashboard or automation
> that referenced it needs editing.
>
> **On an account with several valves or controllers,** the second and later units appear as
> new devices, and the one that was set up before is renamed to carry its Konnect name — its
> entity IDs stay. A single-valve, single-controller account gets no renames.

> 0.4.0 was never published: the multi-device work below was built and run on the author's own
> install as 0.4.0, and released together with the fixes that follow it as 0.4.1.

**Added — every Anthem valve and every Anthem Plus controller on the account, each as its own
device (beta).** Contributed by [@kedube](https://github.com/kedube) in
[#2](https://github.com/frozenmartini/kohler-anthem-plus/pull/2). Until now the integration
took the first valve and the first controller the cloud listed and ignored the rest. An account
with one per bathroom now gets one device per unit, each with the full set of entities, its own
favourites, its own Endless Shower, Warmup Auto-Restore and learned run-time limits, and its
own Cloud Connection sensor. Each valve decodes with the outlet split its own hardware reports,
so a 6-outlet valve and a 3-outlet valve on one account each get the right rows. The one MQTT
stream carries all of them; every message is sorted to its device by id, and a valve's cutoff
and warm-up watchers see only their own valve's traffic. Beta because two valves have run on one
account so far and two controllers on none — please open an issue with how it behaves on yours.

**Changed — device names on an account with several.** With one valve or one controller, the
device is still plainly **Anthem Valve** or **Anthem Plus**, and an existing install is
untouched: unique IDs were already built from the device ID, so entity IDs, history, and
automations stay as they were. With several, each device carries its name from the Konnect
app — **Anthem Valve Master Bath**, **Anthem Plus Guest Bath** — so their entity IDs stay
apart; a unit with no Konnect name, or a duplicated one, falls back to its device ID.

**Changed — `custom_shower` and `send_valve_hex` take a Valve.** Both actions gain a **Valve**
field, a device picker in the automation editor. It is shown only when the account has more
than one valve, the same way Zone 2 is shown only on a two-zone valve; with a single valve the
action uses it unasked. With several, an action that omits it is refused with the valves listed
by name, and picking a controller is refused too. The Zone 2 fields are shown when any valve on
the account has a second zone.

**Changed — per-valve settings.** Endless Shower, Warmup Auto-Restore, the remembered warm-up
mode and the learned run times now live under one `valves` key in the config entry, keyed by
device ID. The flat keys they used to be are moved there once, at the first start after the
update, onto the first valve. No reload, nothing to set again.

**Changed — the valve's Status and a controller's warm-up.** Which controller fronts which
valve is not something the cloud says. With exactly one valve and one controller, they are
taken to be the same shower, as before. With more of either, Status reads the valve alone and
reports `controller_warmup: null`.

**Changed — Repairs and journals.** The Endless Shower "not set up" repair is raised per valve;
the entry-wide one from earlier versions is removed on upgrade. On an account with several
valves, every cutoff and warm-up journal record is stamped with the valve it belongs to; a
single-valve journal is unchanged, byte for byte.

**Changed — diagnostics.** The report gains `valves` and `controllers` lists, one entry per
device with its own layout, plus `valve_count` and `controller_count`. The singular `valve`,
`endless_shower`, `warmup` and `controller` keys stay and describe the first device, so a
report from a single-unit account reads as it did. The "ready" line in the log now lists every
device with the layout it decodes with. The entry section keys per-valve settings by Kohler
device id, and the report leaves those ids in place. A device id is how Konnect names every
product on an account — the valve, the controller, a kitchen faucet, a toilet — and every
message from Kohler's cloud carries one to say which device it is about; it is an address
label, and it opens nothing on its own, since every cloud call needs the account credentials,
which are redacted. Earlier wording in the README and the diagnostics module said the ids were
redacted too; they never were. [@kedube](https://github.com/kedube)'s fork relabels them in
its own reports, which is what brought the mismatch to light — the wording is corrected here,
and the relabelling was not taken up, because the id is the one thing that says which device
a report is about.

**Fixed — the Report Log now captures the whole story.** Turning the switch on records not
just every raw MQTT message but every decision the integration made about them — the run-time
cutoff detector's trail (each zone start and stop, each close it judged, the verdict and why)
and the warm-up watcher's (each mode change, who wrote it, what Auto-Restore did) — in the
**same file**, in the order they happened, on one clock. Records are told apart by their keys:
a raw message has `topic`, a decision record has `journal` (`cutoff` or `warmup`) and `event`.
The decision records are written whether or not Endless Shower and Warmup Auto-Restore are on,
so a report from an install with both off still shows a cutoff that was seen and skipped. One
switch, one attachment.

**Fixed — the integration no longer writes an always-on developer capture on every install.**
Since 0.1.0 every install has been writing three capture files to
`/config/kohler_anthem_plus_raw/` — raw MQTT, the cutoff journal, the warm-up journal — pinned
on by constants meant for the author's own debugging, never pruned, and never described as
something a user had asked for. That was the author's tooling shipping by mistake. It is out
of the published integration now; the trails it carried go into the Report Log instead, above.
The Repairs card described at the top offers to delete the leftover folder.

**Fixed — three things GitHub Copilot's review of #3 caught.** `send_valve_hex` now refuses
a Zone 2 word for a valve that has no second zone — with several valves on an account the
form shows Zone 2 whenever any of them has one, and the word used to be sent as given; all
zeroes is still accepted as "no zone 2". And a valve's or a controller's outlet layout is
now latched only once its own configuration has actually reported one; a first read with no
layout in it used to pin the entry's layout for the life of the entry, which on a two-unit
account could be the wrong one. The read is retried on the next reconnect (entities already
built keep their count until a reload).

**Removed — the "Start new MQTT capture" button.** It rolled the developer capture that no
longer ships, so there is nothing for it to do. The entity is removed from the device page on
upgrade and its registry row cleaned up automatically.

**Changed — Repairs.** One new fixable issue, `old_capture_folder`, offers to delete the
leftover capture folder described above; Submit deletes it only if it holds nothing but the
files this integration wrote.

**Upgrading:** update through HACS and restart Home Assistant. No config changes to make; the
per-valve settings move happens on the first start. On an account with one valve and one
controller, no entities are renamed; one entity — the "Start new MQTT capture" button — is
removed. On an account that already had several units, the second and later ones appear as new
devices; the one that was set up before is renamed to carry its Konnect name and keeps its entity
IDs, since those are held in the entity registry. The Report Log switch's current state and its
files are unaffected. If `/config/kohler_anthem_plus_raw/` exists, a Repairs card offers to delete
it.
