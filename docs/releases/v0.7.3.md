**Fixed — the water total read four times too high.** The valve counts water in
quarter-gallon ticks, not gallons. Confirmed against the owner's two valves and what the
Kohler Konnect app displays for the same fixtures:

    left    raw 8224   ->  2056.00 gal     app  2056.00
    right   raw 25955  ->  6488.75 gal     app  6488.80

Two valves with unrelated totals, both landing on the app's figure to the cent. The capture
corpus agrees from the other direction: it holds `413.25` from one install and `1653` from
another, and `413.25 x 4 == 1653` — the same counter in both scales.

**Both scales are real, so this is not a blanket divide.** A tick count is a whole number by
construction; a gallon figure carries the quarter fractions the scale produces. A reading
with a fraction is already in gallons and passes through untouched.

Neither the reference integration nor the upstream library scales this field — both would
over-report by 4x on this hardware. Their "gallons" reading traces to a single hand-written
line in a reverse-engineered API document that was never calibrated against a device.

**The sensor is `total_increasing`, so the correction is a step down in long-term
statistics.** History already recorded at the old scale keeps its old values; Home Assistant
treats the drop as a meter change rather than negative usage, so no phantom consumption is
recorded.

**Entity names now carry the zone as a number, and only where there is a second zone.**

| | single-zone valve | multi-zone valve |
|---|---|---|
| numbers | `Temperature`, `Flow` | `Temperature 1`, `Temperature 2` |
| fixtures | `Rainhead`, `Showerhead` | `Rainhead 1`, `Rainhead 2` |
| repeated fixture | `Showerhead 1`, `Showerhead 2` | `Showerhead 1.2` — the second in zone 1 |
| unknown outlet | `Outlet 1` | `Outlet 2.1` |

The number trails rather than leading, so related entities sort together in every list —
`Temperature`, `Temperature 2` rather than `Temperature` stranded away from
`Zone 2 Temperature`. Where a zone number and a fixture number would otherwise sit side by
side as two bare numerals, they combine as `1.2` instead of the unreadable `Showerhead 2 1`.

**`Shower Valves` is now `Shower on`**, which says what the switch does.

**Fixed — Firmware reported the artwork version.** 0.7.2 made the sensor resolve, but a valve
publishes several OTA records distinguished by `firmwareType`, and it read whichever arrived
first. That was `Assets` — the bundled UI artwork, versioned separately — so a valve running
application firmware `2.20` reported `2.00`. The `Application` record is now preferred, and
`updatedVersion` (what is running now) is read ahead of `initialVersion` (what it replaced).

**Unique ids are unchanged throughout.** Every rename here is a display name; history and
automations carry over untouched.

**Tests: 29 → 38.** The water scaling is pinned to the owner's two readings and to both
corpus scales, and the naming scheme is checked for name and unique-id collisions across
every platform on a fully-duplicated two-zone valve.
