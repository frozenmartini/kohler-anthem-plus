Three audits — privacy, performance, and security — against the whole integration. Six real
findings, four of them mine from the last two days.

## Your device ids are no longer in the log

**They were printed at INFO on every startup.** `home-assistant.log` is the file people paste
into issues, and that line handed over every valve and controller cloud address on the
account — exactly what `diagnostics.py` goes to length to redact. The startup line now names
the device and its SKU; the ids stay in diagnostics, where they are labelled and redacted.

**Every error message from a read carried one too.** Read endpoints put the id in the path,
and `KohlerError` was built from that path — so ids reached WARNING and ERROR logs, the
`probe_usage` report file, and service responses. Paths are now redacted to `<id>` at the
point the error is raised, which fixes all three at once and keeps the message just as useful
(`gcs-usage/<id> failed with HTTP 400` still says which endpoint and why). Command endpoints
carry no id and are untouched.

**A device name could *become* an id.** With two devices sharing a Konnect name, the
disambiguator fell back to the raw device id — which then lands in entity ids, the dashboard
and every screenshot, permanently. It now numbers them.

The raw MQTT capture also gained the warning its sibling already had: those files contain
device identifiers and show when the shower was used.

## Two safety fixes

**A rotated refresh token was often never saved.** Kohler retires a refresh token the instant
it issues a replacement, and persisting the replacement was the caller's job — but on a
push-only install those callers run once at startup. So tokens rotated for hours with nothing
writing them back, and a restart in that window loaded a token Kohler had already retired,
forcing a re-authentication that nothing had gone wrong to deserve. Persistence now happens at
the rotation itself.

**`send_valve_hex` could command 216 °F.** It is the one path that reaches the valve without
`encode_word`'s clamp, and validation checked only that the word was hex of the right length.
A 10-bit temperature field means a typo could encode 102.3 °C. Whether the firmware would
honour it is untested — and this integration should not be the thing depending on that
answer. The word is now decoded and refused above the 48.8 °C ceiling every other path
enforces. Outlet, flow and pause bits stay unrestricted: that is what the escape hatch is
for, and none of them can scald.

Also closed: the 401 retry called `async_refresh` directly, around the lock added in 0.7.0 to
stop two callers redeeming the same rotating token. It now goes through the locked path.

## Three performance fixes

**The monthly water sensor rebuilt a 13-month history on every MQTT message** — two linear
scans, two `strftime` calls and thirteen conversions, for data read once at setup and never
again. Because attributes are serialised into the state machine and the recorder, that churn
was also being written to the database on every message. Now built once per payload and
cached, invalidated by identity so a re-seed refreshes it. Mine, from 0.8.0.

**Startup made every cloud read in series** — around fourteen round trips on a two-valve,
two-controller account, several seconds of waiting on every restart and reload. Devices are
independent, so they now seed concurrently; the ordering that matters *within* a device
(settings before state) is unchanged.

**A three-hour timer was destroyed and rebuilt on every valve message.** The deadline is
decided by a timestamp, not by the timer, so it is now armed once and compares when it fires.

## What the audits found already correct

Reported because they were verified, not skipped: no blocking I/O on the event loop (the SSL
context is built off-loop, which is the most common cause of Home Assistant's blocking
warnings); no eager f-string log formatting anywhere; no unbounded growth; no polling at all
(`SCAN_INTERVAL` is None and there are no interval timers); TLS verification never weakened;
the MQTT decode path hardened against malformed payloads; `custom_shower` fully clamped on
every axis; no path traversal in any generated filename; and the diagnostics redaction,
including the dictionary-key fix, complete against its threat model.

**Tests: 57 → 61.**

**Upgrading:** update through HACS and restart Home Assistant. No entity ids change unless two
of your devices share a name, in which case they gain a number instead of an id.
