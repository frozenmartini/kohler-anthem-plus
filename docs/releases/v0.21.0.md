**`Favourite` is now `Favorite`**, on both the valve and the controller.

## Why

The entity was named `Favourite` on the stated grounds that *"the Konnect app calls these
favourites"* — which is what its own module docstring said. The app uses the **US spelling**,
so the premise was wrong: the name did not match the thing it was named after.

Renamed throughout the entity layer, the prose and the documentation. Historical release
notes are left as written, since they are a record of what shipped at the time.

## What did not change

⚠️ **The unique id and the state attributes keep the `favourite` spelling.** They are
identifiers rather than display text:

* Moving the unique id would orphan every automation and all recorded history.
* Renaming `favourite_count` or `no_favourites_reason` would break anything reading them.

**Your entity ids are unaffected.** Home Assistant derives an entity id from the name only
when the entity is first created, so `select.anthem_valve_favourite` keeps the id it has.
If you would rather it read `_favorite`, that is a manual rename in the UI — and it will
break anything referencing the old id, which is why it is not done for you.

**Nothing on the wire changed.** Kohler's own protocol vocabulary for these is `preset`,
which was never in scope, and the one API method involved was already US-spelled.
