A documentation correction. `maximumOutletTemperature` is a **setting**, not a hardware
ceiling, and 0.12.0 described it as the latter in three places.

## What actually happened

The owner's two valves reported different scald limits — 450 tenths (113 °F) and 477 tenths
(117.9 °F) — and this project read that as a fixed per-valve hardware property, going as far as
stating that the 113 valve "will still refuse 118".

It will not. The owner set 118 °F in the Konnect app and the next diagnostics download, seven
minutes later, read **477 tenths on all three outlets**. It is an ordinary setting that
happened to differ between two showers, probably since installation.

Nothing in the code depended on the wrong belief — the sensor reported the live value
correctly throughout, and tracked the change — so this release only fixes what the code *says*
about itself, plus two tests that pin the behaviour:

* `Max Temperature` reports the ceiling **in force now**, which can move at any time.
* The temperature slider must **not** derive its bounds from it. That would have been the
  intuitive next step and is the wrong one: a user-configurable limit would make the slider
  silently reshape itself whenever somebody changed a setting, and Home Assistant caches an
  entity's bounds, so widening one would need the entity rebuilt.

## An incidental confirmation

Kohler stored `477` tenths for the 118 °F the owner selected, and this integration's own
`unit_to_celsius(118, "Fahrenheit")` produces 47.7 °C — 477 tenths. The conversion table and
Kohler's firmware agree on what "118 °F" means, which is worth knowing given how much of this
project turns on units.
