Three fixes taken from upstream `frozenmartini/kohler-anthem-plus` v0.4.1 — two real bugs this
fork also had, and one improvement worth adopting. Credit to that release, and to GitHub
Copilot's review which found the first two.

## The outlet layout could latch on a read that said nothing

`_topology_checked` was set to `True` and *then* `_apply_topology` was called. So a first
`gcsadvancestate` read carrying no layout latched anyway, and the valve **never tried again** —
it kept the model the config flow chose, which is the model the *first* valve reported.

On an account whose valves differ, that leaves the wrong outlet layout on every valve but the
first, permanently, decoding and encoding every word with it. `_apply_topology` now returns
whether the read actually answered, and the caller latches on that, so the next reconnect gets
another chance. A read that answers and agrees still latches — otherwise it would re-read for
ever.

Not visible on an account whose valves share a layout, which is why it survived this long.

## `send_valve_hex` sent a Zone 2 word to a valve with one zone

The action shows the Zone 2 field whenever **any** valve on the account has a second zone — so
on a mixed account it is offered for a single-zone valve too, and the word was encoded and sent
to a valve with nothing to receive it.

It is now refused by name, saying which valve and that nothing was sent. All zeroes stays
legal: that is the sentinel a single-zone valve genuinely uses, and the branch below produces
it anyway. Only a word that tries to *command* a zone that does not exist is refused.

## The Report Log now carries the reasoning, not just the wire

Turning the switch on recorded every raw MQTT message. It now also records every **decision**
made about them — the run-time cutoff detector's trail and the warm-up watcher's — in the same
file, in the order they happened, on one clock.

A raw message has `topic`; a decision has `journal` (`cutoff` or `warmup`, since the two
vocabularies reuse event names) and `event`:

```
jq -c 'select(.topic)'    report_*.jsonl   # the wire
jq -c 'select(.journal)'  report_*.jsonl   # the reasoning
```

Decisions are written **whether or not Endless Shower and Warmup Auto-Restore are on**, so a
report from an install with both off still shows a cutoff that was seen and deliberately
skipped — usually the question being asked. The standalone journals are unchanged and still
written; this is a copy into the report, not a move.

One switch, one attachment.

## Not taken

* **The `old_capture_folder` Repairs flow.** Upstream's headline fix was that every install
  before 0.4.1 wrote an always-on developer capture. This fork already has
  `ENABLE_RAW_MQTT_LOG = False` and never shipped that, so there is no leftover folder to
  offer to delete.
* **Removing the "Start new MQTT capture" button.** It rolls the development capture, which
  this fork still has and keeps switched off.
* **The device-id wording change.** Upstream corrected its docs to say ids are not redacted;
  this fork redacts them, which is a deliberate divergence and stays.
