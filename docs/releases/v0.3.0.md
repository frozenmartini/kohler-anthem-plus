**Added — `kohler_anthem_plus.custom_shower`, a one-command shower you can build in the
automation editor.** Turn on the outlets, set each zone's temperature, optionally a flow, and it goes to
the valve as a single command. This is the answer to
[#1](https://github.com/frozenmartini/kohler-anthem-plus/issues/1): an outlet switch followed
by a temperature change is two commands, the second is built from a report that predates the
first, and it closes what the first opened. `custom_shower` sends one — everything it writes
comes from the form, nothing from the valve's last report. Outlets you leave off are
closed; leave them all off to stop.

**Added — "No pausing warm-up" (beta).** Keeps the shower on after the valve's warm-up is
finished. On a valve with warm-up enabled, every
command warms up and then *pauses* for two minutes, just as it always does — so a command from Home
Assistant has never produced a running shower by itself on such a valve. With this on,
`custom_shower` watches the valve's own reports and, when that pause arrives, sends your
outlets and temperature again, once. Off by default; nothing changes for the outlet switches.
Beta because it has run on one valve so far — please open an issue with how it behaves on
yours.

**Fixed — the `send_valve_hex` response.** Its `decoded` field returned the last zone's raw
decode instead of the two-zone description. Both actions now return the words they sent and
the reading of each.

**Docs — one valve command at a time.** Why two back-to-back valve commands undo each other,
when a 3 s delay is enough (warm-up off) and when it is not (warm-up on), in the user guide
and `docs/gcs/api.md` §2. The README gains a **Custom shower service** section with two
screenshots of the action in the automation editor.

**Upgrading:** update through HACS and restart Home Assistant — the new action appears after
the restart. No config changes, no entities renamed or removed.
