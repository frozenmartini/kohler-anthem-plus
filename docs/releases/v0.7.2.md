**`Zone 1 Active` is now `Shower Active`.** On a single-zone valve there is one shower, and
`Zone 1` said nothing you could act on. A two-zone valve still shows `Zone 1 Shower Active`
and `Zone 2 Shower Active`, where the prefix is doing real work.

The unique id is unchanged, so history and any automation referencing the entity carry over
untouched.

**Fixed — the Firmware sensor read `unknown`.** It looked for `about.firmware` in
`gcs-configuration`. That is the shape the reference install reports; the owner's two K-28210
valves have **no `about` block at all**, so the lookup could never resolve and the sensor sat
at `unknown` on that hardware from the day it shipped.

Kohler does not put the version in one place, so the sensor now tries each known shape in
turn: `about.firmware`, then `otaReportedProperties` (including the Azure IoT device-twin
form, where the live values sit under `reported`), then `firmwareUpdate`, then a bare
top-level `version`. Numbers are accepted and stringified.

**A version the cloud *wants* installed is never reported as the one running.** Only
current-shaped keys are read; a `firmwareUpdate` carrying just a `targetVersion` yields
nothing. Where no shape matches the sensor still reads `unknown`, which is deliberate — a
confidently wrong version in a bug report is worse than a blank one.

**Diagnostics now include the version blocks.** The summariser named `firmwareUpdate`,
`otaReportedProperties` and `version` without ever saying what was in them, so the one
question a firmware report exists to answer needed a second round trip to the hardware. These
three blocks are version strings and update state — no plumbing structure, no identity — and
are now reported in full. Everything else in that block is still summarised by key name, as
before.

If your Firmware sensor still reads `unknown` after this release, download diagnostics and
the `version_blocks` section will show what your valve actually reports.

**Tests: 16 → 29.** Both fixes are covered, including twelve firmware shapes and the two
traps above. The firmware test exercises the real property rather than the test double —
the first draft asserted against a hardcoded attribute on the stand-in and passed one case by
coincidence, which is precisely the class of gap the 0.7.0 review called out. Each new test
was verified to fail against the old code before being kept.

**Upgrading:** update through HACS and restart Home Assistant. The Firmware sensor is
diagnostic and disabled by default; enable it on the valve device if you want to see it.
