A new **`Water Used This Year`** sensor: the last twelve complete months of Kohler's own usage
history, summed.

## Why a year rather than a lifetime

The valve reports a lifetime counter, `totalVolume`, and it does track water — an isolated
session measured on the reference hardware moved it by **19 counts for 2.4 gallons**, which
makes it eighths of a US gallon to within 1%.

But its absolute value is around **537 million**, and 537 million eighths is 67 million
gallons. A shower valve would have to run continuously for decades. Something else is packed
into that field — the high 16 bits were identical across every reading while only the low bits
moved — and until somebody establishes what, a lifetime total derived from it would be a guess
dressed as a measurement.

`gcs-usage` needs none of that. It returns a per-month series in **litres**, it is the same
data the Konnect app charts, and its units were settled when the endpoint was cracked. Summing
twelve entries is arithmetic on numbers whose meaning is already known.

A year is not a lifetime. It is, however, a real number that matches the app — which is worth
more than a lifetime figure that does not.

## Details

* **Complete months only.** The current partial month is excluded, so the value changes once at
  a month boundary rather than creeping upward all month and dropping when the window rolls.
  `Water Used This Month` covers the partial month beside it.
* **`TOTAL`, not `TOTAL_INCREASING`.** A rolling window falls whenever the month dropping off
  the back was wetter than the one joining; calling that a meter reset would inject a phantom
  year of water into long-term statistics.
* **No new API call.** The 400-day series is already fetched once at setup for the monthly
  sensor; this sums what is already in memory, cached on the payload's identity so it does not
  recompute on every MQTT message.
* **A short series is reported honestly** — `months_counted` says how many months were
  available, so a young account does not read as a dry year.

`Total Water Used`, which reads `totalFlow`, is **unchanged and still suspect** — that field
takes only three distinct values across the whole reference corpus and shifts between two
scales exactly 4× apart. It is not fixed here; it is simply no longer the only water figure
available.
