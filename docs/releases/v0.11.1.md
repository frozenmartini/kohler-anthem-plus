Two limit sensors, named and measured the way the Konnect app names and measures them.

## `Rainhead Max Run Time` is now `Max Shower Duration`, in minutes

**The old name described the wrong thing.** It was named after outlet 1's fixture, which read
as a property of that fixture — but the limit is timed **per zone**, every outlet on the
reference install reports the same figure, and only one entity was ever created. "Max Shower
Duration" is what the app calls it.

**And it was reported in seconds.** The valve reports `maximumRunTime` as `1800`, which this
published raw, while the app, the touchscreen and Kohler's own documentation all say
"30 minutes". It now reports `30`. The conversion happens in the sensor rather than being left
to the frontend, because the stored value is what automations and history read.

The unique id is unchanged, so history and any automation referring to it carry over.

## New: `Max Temperature`

🚨 **The scald limit** — `maximumOutletTemperature`, the ceiling the valve will not exceed
however it is commanded, and otherwise visible only in the Konnect app. 118 °F on the
reference system.

It was being read from the valve and discarded: the outlet-configuration parser took six
fields per outlet and dropped the rest. Both sources are now read, and they disagree about
units in the same way they disagree about flow — REST reports display °C (`45`, `47.8`), MQTT
reports tenths (`450`) — so both are normalised to tenths on the way in. Getting that wrong
would misreport a safety setting by a factor of ten, so it is covered from both directions.

Published in the account's own unit, like every other temperature here, and `unknown` until
the valve has reported it — which is not the same as "no limit".

**Read-only.** This integration never writes it; `docs/gcs/api.md` warns that a whole-record
write which omits it, or sends it on the wrong scale, silently changes it.
