**A full code review, and the two security fixes it found.** This release contains no new
features. It is the result of reading all 15,742 lines against the captured API and MQTT
data, and fixing what that turned up. Two findings are worth updating for on their own.

**Diagnostics published your device ids.** The diagnostics download redacted tokens and
passwords correctly, but printed every valve's device id in plain text — verified against
two real diagnostics files. Kohler device ids double as cloud addresses, so they belong
with the credentials, not in a file the documentation tells you to attach to a public
issue. The cause was narrow: `async_redact_data` replaces the *values* at listed keys and
recurses into nested dictionaries, but never touches dictionary *keys* — and the valve
section is keyed by device id. Valves are now relabelled `valve_0`, `valve_1`, matching the
labels the rest of the report already used.

If you have attached a diagnostics file to an issue or shared one, it contains your device
ids. Re-downloading now produces a clean file.

**Two token refreshes at once could sign you out.** Kohler issues rotating refresh tokens —
redeeming one invalidates it and returns the next. Nothing serialised the refresh, so when
several requests found the token expired together, the first succeeded and the rest
redeemed a token that was already spent, surfacing as a spurious prompt to re-authenticate
against credentials that were fine. Reproduced with four concurrent callers: three failed.
Refresh now runs under a lock with a second check inside it, so late arrivals use the token
the winner fetched.

**Three diagnostic captures shipped switched on.** The raw MQTT capture, the cutoff log and
the warm-up log were all forced on in 0.6.7. The MQTT capture overrides its own logger
switch when forced, so it could not be turned off from the UI, and nothing pruned the
files. All three are off by default again, as documented, and the cutoff log — which had no
size cap at all — now rolls at a bounded size.

**Also fixed:** the warm-up restore task could outlive an unload and write to the valve
sixty seconds later; a setup failure after `async_setup` leaked the MQTT stream, file
handles and timers, and each `ConfigEntryNotReady` retry stacked another set; the
temperature slider could display a value the valve would then reject; a cloud check that
never ran still consumed its thirty-minute cooldown. A dead preset encoder using the
superseded temperature formula — 25.6 °C off on cold presets, and silently dropping the
outlet mask — was deleted rather than repaired.

**The repository now uses the standard layout.** The integration moved to
`custom_components/kohler_anthem_plus/` and `content_in_root` is gone from `hacs.json`.
This was not cosmetic: `select.py` sitting at the repository root shadowed Python's standard
library `select` module, which `asyncio` imports.

**There are tests now, and CI runs them.** Sixteen, covering every platform's real
`async_setup_entry` against both valve types, including a direct regression test for the
0.6.6 deletion and unique-id collision checks. CI previously validated only the manifest and
never imported a single Python file — which is exactly how 0.6.6 shipped green with two
entities missing.

**Documentation.** The user guide's entity tables were wrong in nearly every row; six
releases of renaming landed without them. Both the README and the guide still said there was
no flow control, which stopped being true in 0.6.0. Install instructions described the old
layout. Two errors in earlier release notes are corrected: 0.6.6 claimed three Max Run Time
sensors where there is one, and 0.6.0 claimed five confirmed outlet type codes where four
are confirmed.

**Upgrading:** update through HACS and restart Home Assistant. No entity ids change and no
reconfiguration is needed.

**Known gaps.** The test suite does not yet construct controller (HUB) entities, so roughly
half the entity classes are covered by review rather than by test. `FLOW_PER_PERCENT`
remains hardcoded and is only correct for installs reporting `maximumFlowRate: 200`.
