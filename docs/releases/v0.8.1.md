**Fixed — `probe_usage` outlived the integration.** Added in 0.7.7 and registered correctly,
but never added to the unload path: after the last config entry unloaded, the action stayed
in Home Assistant's registry with nothing behind it. Calling it then reported *"No Anthem
valve on this account"* — an error about entirely the wrong thing — and it lingered in the UI
after the integration was removed.

A test now reads both the registration and unregistration functions and asserts every service
in one appears in the other, so a future service cannot repeat this. A second test asserts
every registered service is described in `services.yaml`, since one that is not appears in
the UI with no name, description, or fields.

**Fixed — the warm-up give-up warning could not fire.** When something outside Home Assistant
keeps rewriting a valve's warm-up mode, the auto-restore stops after five attempts. It was
supposed to log a warning saying so — the one thing that would tell an owner their valve is
being fought over — but the warning sat behind a test for *more than* five, on a counter that
a gate above stops at five. Reaching six was unreachable in practice.

The warning now fires where giving up actually happens, latched so a persistent fight logs
once rather than on every attempt, and cleared when the mode stays enabled so a fight that
stops and restarts is reported again.

**Controller entities are tested for the first time.** Roughly half the entity classes belong
to the Anthem Plus controller and not one had ever been constructed in a test — the same
blind spot that let 0.6.6 ship with two valve entities silently missing. Four tests now build
every controller platform, check a controller and a valve never collide on an id, cover two
controllers on one account, and pin the naming.

**Fixed — a controller said `Zone 1 Temperature` where its valve said `Temperature`.** Found
by those new tests. The 0.7.3 renaming reached valve entities only, so two views of one
shower read as two different things. The naming helper now takes either device.

**Dead code removed.** `describe_zones`, and five members of the measurement block —
`_measuring_word`, `reports_measurements`, `measured_temperature`, `measured_flow_percent`
and `warmup_enabled` — all wrappers for a binary sensor removed in 0.6.x, with no call sites
since. The *decoded fields* they wrapped are untouched and still published on the Hex sensor
and in diagnostics; only the unused `GcsState` wrappers are gone. What the docstrings knew is
kept as a comment: a valve that does not populate the measurement block reports temperature
**and** flow as zero together, and any future reader must gate on both.

**Six of ten previously-flagged items turned out not to be defects**, and are documented as
such rather than silently dropped: the preset seed is consumed correctly, the MQTT stop path
leaks nothing, the auth retry is deliberately unbounded with a once-per-outage notification,
the broad `except` in the reconnect loop is correct there, `_resolve_valve` guards ambiguity
by raising rather than guessing, and the switches' optimistic state is cleared on every path
that can set it.

**Tests: 48 → 54.**

**Upgrading:** update through HACS and restart Home Assistant. No entity ids change.
