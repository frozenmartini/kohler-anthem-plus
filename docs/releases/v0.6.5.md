**Changed — the valve's `Shower` switch is now `Shower Valves`.** Beside the outlet switches
that 0.6.0 renamed — `Rainhead`, `Showerhead`, `Handshower` — a plain "Shower" read as one
more outlet. It is the opposite: the whole-shower control that drives the valves themselves,
where each outlet switch opens a single outlet at whatever temperature the zone already
holds. The name now says which thing it acts on rather than what the water comes out of.

**Your entity ID does not change.** The rename is the display name only; the underlying
identifier is untouched, so `switch.anthem_valve_shower` keeps working and no automation,
script or dashboard card needs updating. That is a deliberate difference from the outlet
rename in 0.6.0, which did change IDs — those replaced a name carrying no information at
all, which was worth the breakage. This one is a clarification, and clarity is not worth
breaking working automations for.

The Anthem Plus controller's own `Shower` switch keeps its name. It is a different control
on a different device — it opens the *controller's* default outlets, a separate setting from
the valve's — and on a controller the name was never ambiguous, since no outlet entities sit
beside it.

**Docs — the entity tables and the two-devices comparison are updated** to match, including
the note that a valve and a controller in the same room can start two different showers.

**Upgrading:** update through HACS and restart Home Assistant. Nothing to change: the switch
appears under its new name and keeps the entity ID it already had.
